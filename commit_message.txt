🧹 refactor(human_interaction): encapsulate human_type config in dataclass

🎯 **What:** The `human_type` function had too many boolean and dict parameters related to typing profiles, typos, and hesitation logic. These were grouped into a new `HumanTypeConfig` dataclass.
💡 **Why:** Reduces parameter footprint, improves code readability, and provides a clear mechanism to store/pass the typing behavior parameters around without updating function signatures in multiple places.
✅ **Verification:** Verified by running full integration tests for anti-detection (`pytest tests/test_anti_detection_integration.py -v`). No regressions found.
✨ **Result:** Improved maintainability for human simulation behavior logic without changing any core logic or automation behavior.
